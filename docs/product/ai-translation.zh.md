# AI 翻译 AI Translation

AI Translation 为 XBuilder 中的动态说明提供按需翻译，帮助用户用所需语言理解代码和内容。

## 背景

当前 XBuilder 的固定界面已有多语言文案，但编辑器中的诊断会随代码变化，库文档也包含不同语言的说明，此外 UGC 内容的翻译也是后续的发展方向。AI Translation 为这些内容提供统一的翻译入口。

编辑器已有中英文内置说明，包括 XGo 的 `for`、`if`、`var`、`println`，以及 Spx 的 `Sprite`、`clone`、`onCloned`、`turn` 等。

## 目标

* 一期支持代码编辑器 Hover 中的诊断说明和文档说明。
* 用户主动请求翻译，保留原文供对照，译文忠实于原义。
* 结合说明对象选取上下文，保持专业术语、代码名称和格式准确。
* 等待翻译期间可继续编辑和阅读。
* 长期按阅读需求扩展至项目描述、操作说明、课程介绍等 UGC 动态内容。

## 基本概念

### 说明 Description

* 诊断说明：描述代码中的问题，对应诊断的文件和范围。
* 文档说明：描述类型、方法等定义，来自库文档或用户注释。

翻译以完整说明为单位，将混合语言正文统一表达为目标语言，保持原义和语句衔接。签名、代码标识符、示例代码、数字、链接和 Markdown 结构保持原样。

### 上下文 Context

Context 是随说明提供的相关背景，由前端在翻译请求前读取和筛选。诊断按报错位置定位，文档按所属定义定位，每次请求固定正文和选取的信息。

#### 诊断说明

| 所需信息 | 读取入口 |
| - | - |
| 诊断正文与位置 | `Diagnostic.message` 提供正文，`Diagnostic.range` 提供范围；文件取诊断外层或 Hover 的 `textDocument.id` |
| 报错表达式和相关代码 | `codeEditor.getTextDocument(id)` 取得文本对象，再用 `textDocument.getValueInRange(range)` 或 `textDocument.getLineContent(line)` 读取代码 |
| 涉及的声明、类型和参数 | `codeEditor.lspClient.textDocumentDefinition`、`codeEditor.lspClient.textDocumentTypeDefinition` 返回声明位置，再通过文本对象读取代码 |
| 涉及的资源名称和类别 | `codeEditor.lspClient.getResourceReferences` 返回资源引用，独立函数 `getResourceModel(project, resourceId)` 取得资源对象 |

相关声明和资源信息按诊断内容补充。

#### 文档说明

| 所需信息 | 读取入口 |
| - | - |
| 定义名称、签名、所属包或类型 | `DefinitionItem` 已持有 `overview`、`defId` 字段；独立函数 `parseDefinitionId` / `parseDefinitionName` 解析包名、定义名及所属类型 |
| 说明正文及已有语言版本 | `codeEditor.documentBase.getDocumentation(defId)` 读取库说明；`DefinitionDetail` 的 `childrenText` 承接语言服务正文 |
| 用户注释涉及的声明或实现片段 | `codeEditor.lspClient.textDocumentDefinition` 返回声明位置，再用 `textDocument.getValueInRange(range)` 读取源码 |

两类翻译涉及的 XGo / Spx 知识，分别通过 `utils/xgo`、`utils/spx` 导出的独立函数 `getXGoLanguageSkillFiles()`、`getSpxProjectSkillFiles()` 读取，按语法和 API 选择资料。

## 核心机制

### 语言分析

目标语言采用阅读者的当前界面语言。

| 环节 | 处理方案 |
| - | - |
| 读取 | 前端优先使用内置文档、页面缓存或内容接口提供的语言信息；缺少有效信息时请求语言分析接口 |
| 识别 | 缺少有效结果时，语言分析服务调用模型一次，识别正文中的自然语言；代码、按键名和专有名称作为受保护内容处理 |
| 标记 | 保存自然语言的语种列表和识别状态；混合语言记录为 `[zh, en]` 等列表，受保护内容排除在语种标签之外 |
| 比较 | 将自然语言标签与目标语言比较，得到同语种、包含其他语种或无法确定的判断结果 |

例如正文“按空格跳跃，avoid the enemies”标记为 `[zh, en]`，中文和英文阅读者均可看到翻译入口。“按 Space 跳跃”中的按键名保持原样，自然语言标记为 `[zh]`。

两类内容的语言分析时机如下：

* 公共 UGC：正文保存或更新后识别语言，用户阅读时随正文返回语言信息。
* 编辑器说明：用户查看时查询正文的语言信息，缺少有效结果时再识别。

### 内容选择

翻译对象是用户当前阅读的说明正文，按以下规则展示：

| 内容状态 | 展示规则 |
| - | - |
| 已有目标语言内置文档 | 直接展示该语言的文档 |
| 正文的自然语言内容已完整使用目标语言 | 直接展示正文 |
| 正文包含其他语言的说明片段 | 展示原文和“翻译”入口 |
| 已保存适用于当前内容的译文 | 展示原文和“翻译”入口，用户点击后读取并展示译文 |
| 仅包含签名、代码或空正文 | 保留现有展示 |
| 语言分析进行中 | 展示原文，分析完成后确定翻译入口 |
| 语言分析失败或语种难以确定 | 展示原文和“翻译”入口 |
| 用户点击后等待译文 | 保留原文并显示进行中状态 |
| 用户点击后译文可用 | 展示带有 AI 翻译标识的译文，保留原文供对照 |

### 接口设计

两个接口共用内容来源、实际正文、正文格式和保护名称，译文接口另接收目标语言和 Context。诊断与注释由前端提供正文，公共内容由后端按来源标识读取或核验。

| 接口 | 触发时机 | 职责与返回 |
| - | - | - |
| `POST /translations/language-analysis` | 缺少有效语言信息时自动调用 | 查询或识别正文语言，返回语种列表、识别状态及是否包含自然语言，供前端判断翻译入口 |
| `POST /translations` | 用户点击翻译，页面内缺少可复用结果时调用 | 查询已有译文或等待同一任务；需要生成时检查额度与频率并调用模型一次，返回完整译文 |

### 翻译流程

1. 前端读取或自动识别正文语言，与界面语言比较后决定是否展示翻译入口。
2. 用户点击后，前端收集 Context，优先复用页面内的译文或任务；缺少结果时调用译文接口，由后端查询或生成。
3. 生成完成后核对当前输入及公共内容版本，校验成功的结果按内容类型保存，并展示与当前说明及目标语言匹配的译文。

### 结果保存

语言信息保存语种和识别状态，供不同目标语言共用；译文保存完整内容、目标语言及对应的正文、背景和规则依据。

| 内容 | 保存方式 |
| - | - |
| 诊断、用户注释及包含个人代码背景的译文 | 当前用户的页面缓存保存语言信息、任务和译文 |
| 已有中英文内置说明 | 沿用现有文档资源 |
| 稳定公共库说明及后续公共 UGC | 数据库保存语言信息和成功译文，Redis 加速读取；相同公共背景下共享结果 |

页面缓存设置有效期和容量上限，刷新页面或切换账号后清理。离开 Hover 后任务继续，返回已点击的同一说明时显示进度或译文。

每份公共说明保留一条当前正文记录，每种目标语言保留一条译文记录；同一语言的新结果覆盖原记录。Redis 缓存缺失或过期时从数据库读取有效结果并回填。

### 译文更新

正文、保护名称或语言分析规则变化时重新识别语言；仅背景、目标语言或翻译规则变化时复用语言信息。

#### 页面缓存更新

复用编辑器的代码变更通知和诊断刷新机制，重新读取说明正文及 Context；新增正文、保护名称和上下文的匹配指纹，用于查找相同目标语言和翻译规则下的缓存。

说明正文或相关上下文改变后，展示当前原文，用户需要再次点击“翻译”；已有匹配缓存时直接读取，缺少时重新翻译。仅移动行号或修改无关代码时继续使用原译文。

#### 公共记录更新

| 内容 | 更新依据 |
| - | - |
| 公共库说明 | 复用现有定义 ID 和说明读取；新增可信文档清单、正文与公共背景指纹及条目内容版本，识别同一库版本内的说明修改 |
| 项目描述、操作说明（后续） | 复用 `UpdateProjectParams.Diff` 对 `description`、`instructions` 的变更检测；新增每个字段的内容版本，正文或所需公共背景变化时更新 |

项目 `revision` 用于提示重新检查，字段内容版本用于判定译文是否有效。不同库版本或发布对象分别维护记录。

内容版本更新后，各语言旧译文失效，用户需要再次点击“翻译”生成当前译文；成功结果覆盖该语言的原记录并更新 Redis 缓存。其他语言待用户按需生成，当前内容只使用匹配当前版本的缓存。

### 使用额度

翻译复用现有配额与限流机制，在 Free / Plus 套餐内独立计量。

| 套餐 | 生成额度 / 24 小时 | 生成尝试上限 / 1 分钟 |
| - | - | - |
| Free | 1000 次 | 30 次 |
| Plus | 5000 次 | 60 次 |

两个窗口分别从首次成功扣额开始计时，后续请求保持原到期时间；到期后恢复额度，下次请求开启新窗口。分钟额度可集中使用。翻译和 Copilot 分开计数，语言分析由系统独立调度与计量。

计数规则如下：

| 操作 | 额度处理 |
| - | - |
| 查看已有目标语言文档或译文 | 直接读取，两个窗口均保持原计数 |
| 返回正在翻译的说明、重复点击同一任务 | 复用任务，维持原计数 |
| 生成一份新译文 | 预扣一次生成额度，并计入短期尝试次数 |
| 修改原文、相关背景或目标语言后请求新译文 | 缺少可复用结果时按新任务计数 |

### 失败处理

翻译失败时保留原文，并提示原因与后续操作。

| 情况 | 处理方式 |
| - | - |
| 24 小时生成额度耗尽 | 提示翻译额度已用完及可用的恢复时间 |
| 1 分钟生成尝试达到上限 | 提示请求过于频繁及可用的等待时间 |
| 模型调用失败、服务端超时或译文无效 | 提示翻译失败，请手动重试 |

额度或频率受限期间，已保存且仍可访问的有效译文继续供用户点击查看。重试时按当前说明重新匹配译文或任务，需要新生成时重新计数。

## User Story

### 理解诊断

用户编写代码时遇到英文类型错误，点击诊断说明中的“翻译”，理解错误原因后修改代码。

### 阅读库文档

用户学习 Spx API 时遇到缺少中文说明的方法，点击“翻译”，理解方法的用途和参数含义。

### 阅读用户注释

用户阅读他人编写的方法时，点击“翻译”查看外语注释，理解这段代码的意图。

### 阅读 UGC（后续）

用户浏览其他创作者的项目时，点击“翻译”理解外语或混合语言的项目描述和操作说明，了解作品内容与玩法。
