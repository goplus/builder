# AI 翻译 AI Translation

AI Translation 为 XBuilder 中的动态说明提供按需翻译，帮助用户用所需语言理解代码和内容。

## 背景

当前 XBuilder 的固定界面已有多语言文案，但编辑器中的诊断会随代码变化，库文档也包含不同语言的说明，此外 UGC 内容的翻译也是后续的发展方向。AI Translation 为这些内容提供统一的翻译入口。

编辑器已有中英文内置说明，包括 XGo 的 `for`、`if`、`var`、`println`，以及 Spx 的 `Sprite`、`clone`、`onCloned`、`turn` 等。已有目标语言说明直接展示，其余内容由用户按需请求翻译。

## 目标

* 一期支持代码编辑器 Hover 中的诊断说明和文档说明。
* 用户主动请求翻译，保留原文供对照，译文忠实于原义。
* 结合说明对象选取上下文，保持专业术语、代码名称和格式准确。
* 用户离开说明后任务继续，返回已点击的同一说明时复用任务或译文。
* 长期按阅读需求扩展至项目描述、操作说明、课程介绍等 UGC 动态内容。

## 基本概念

### 说明 Description

* 诊断说明：描述代码中的问题，对应诊断的文件和范围。
* 文档说明：描述类型、方法等定义，来自库文档或用户注释。

每份说明单独对应翻译操作。同一个 Hover 中的诊断和文档分别处理。

翻译以完整说明为单位，将混合语言正文统一表达为目标语言，保持原义和语句衔接。签名、代码标识符、示例代码、数字、链接和 Markdown 结构保持原样。

### 上下文 Context

Context 是随说明提供的相关背景，由前端在翻译请求前读取和筛选。诊断按报错位置定位，文档按所属定义定位，每次请求固定正文和选取的信息。

#### 诊断说明

| 所需信息 | 读取入口 |
| - | - |
| 诊断正文与位置 | `Diagnostic.message` 提供正文，`Diagnostic.range` 提供范围；文件取诊断外层或 Hover 的 `textDocument.id` |
| 报错表达式和相关代码 | `codeEditor.getTextDocument(id)` 取得文本对象，再用 `textDocument.getValueInRange(range)` 或 `textDocument.getLineContent(line)` 读取代码 |
| 涉及的声明、类型和参数 | `codeEditor.lspClient.textDocumentDefinition`、`codeEditor.lspClient.textDocumentTypeDefinition` 返回声明位置，再通过文本对象读取代码 |
| 涉及的资源名称和类别 | `codeEditor.lspClient.getResourceReferences` 返回资源引用，独立函数 `getResourceModel(project, resourceId)` 取得资源对象 |

相关声明和资源信息按诊断内容补充。

#### 文档说明

| 所需信息 | 读取入口 |
| - | - |
| 定义名称、签名、所属包或类型 | `DefinitionItem` 已持有 `overview`、`defId` 字段；独立函数 `parseDefinitionId` / `parseDefinitionName` 解析包名、定义名及所属类型 |
| 说明正文及已有语言版本 | `codeEditor.documentBase.getDocumentation(defId)` 读取库说明；`DefinitionDetail` 的 `childrenText` 承接语言服务正文 |
| 用户注释涉及的声明或实现片段 | `codeEditor.lspClient.textDocumentDefinition` 返回声明位置，再用 `textDocument.getValueInRange(range)` 读取源码 |

两类翻译涉及的 XGo / Spx 知识，分别通过 `utils/xgo`、`utils/spx` 导出的独立函数 `getXGoLanguageSkillFiles()`、`getSpxProjectSkillFiles()` 读取，按语法和 API 选择资料。

## 核心机制

### 语言判断

目标语言采用阅读者的当前界面语言。系统通过新增语言分析接口自动识别实际正文，结果绑定正文版本保存，前端读取标签后与目标语言比较。发布者的语言设置排除在识别依据之外。

| 环节 | 处理方案 |
| - | - |
| 读取 | 使用已有内置文档语言信息，或查询当前正文版本的语言分析结果 |
| 识别 | 缺少有效结果时，语言分析服务调用模型一次，识别正文中的自然语言；代码、按键名和专有名称作为受保护内容处理 |
| 标记 | 保存自然语言的语种列表和识别状态；混合语言记录为 `[zh, en]` 等列表，受保护内容排除在语种标签之外 |
| 复用 | 稳定库说明及后续公共 UGC 使用数据库与 Redis，诊断和用户注释使用当前页面的前端缓存；同版本并发识别合并为一个任务 |
| 比较 | 完整识别且全部匹配目标语言时直接展示正文；包含其他语种、识别不完整或识别失败时提供翻译入口 |

例如正文“按空格跳跃，avoid the enemies”标记为 `[zh, en]`，中文和英文阅读者均可看到翻译入口。“按 Space 跳跃”中的按键名保持原样，自然语言标记为 `[zh]`。切换目标语言只重新比较标签，正文更新后重新识别。

语言分析独立于点击后的译文生成。公共 UGC 在正文保存或更新后准备语言信息，阅读时随内容提供；编辑器说明按实际阅读的正文查询或识别。语言分析由系统完成，难以确定时按需要翻译处理，用户通过同一个翻译入口请求译文。

### 内容选择

翻译对象是用户当前阅读的说明正文，按以下规则展示：

| 内容状态 | 展示规则 |
| - | - |
| 已有目标语言内置文档 | 直接展示该语言的文档 |
| 正文的自然语言内容已完整使用目标语言 | 直接展示正文 |
| 正文包含其他语言的说明片段 | 展示原文和“翻译”入口 |
| 已保存适用于当前内容的译文 | 展示原文和“翻译”入口，用户点击后读取并展示译文 |
| 仅包含签名、代码或空正文 | 保留现有展示 |
| 语言分析进行中 | 展示原文，分析完成后确定翻译入口 |
| 语言分析失败或语种难以确定 | 展示原文和“翻译”入口 |
| 用户点击后等待译文 | 保留原文并显示进行中状态 |
| 用户点击后译文可用 | 展示带有 AI 翻译标识的译文，保留原文供对照 |

译文保存状态与用户的展示选择分别管理。同一页面会话内，用户已点击的说明保留查看译文的选择；新会话、内容或目标语言变化后，按当前内容重新判断入口，由用户再次点击查看。

### 翻译流程

1. 前端确定实际说明，通过语言分析接口读取或识别正文语言，与界面语言比较；难以确定时提供翻译入口。
2. 用户点击后，前端收集所需 Context，固定正文、背景和目标语言，形成当前输入标识。
3. 查询当前输入对应的译文或任务：已有译文直接返回，进行中任务继续等待。
4. 缺少结果和任务时，通过译文生成接口请求翻译；服务端检查额度与频率，将固定输入提交模型一次。
5. 校验完整译文，按内容类型保存至前端缓存或公共持久化记录；前端按当前输入和用户展示选择呈现结果。

### 结果保存

系统保存正文的语言信息和成功译文，用于后续阅读时复用。保存范围按内容分类：

| 内容 | 保存与复用规则 |
| - | - |
| 诊断、用户代码注释 | 在当前用户的页面内缓存语言信息、任务和译文 |
| 已有中英文内置说明 | 沿用现有文档资源，直接读取目标语言说明 |
| 缺少译文的稳定公共库说明 | 长期保存，供读取相同版本及公共背景的用户复用 |
| 项目描述等公共 UGC（后续） | 随对应内容保存，供相同目标语言的阅读者复用 |

#### 页面内缓存

用户离开 Hover 后，翻译继续执行并保存结果。返回已点击的同一说明时，可以查看进行中的任务或已完成的译文。

页面内缓存受使用时间和容量限制；刷新页面或切换账号后清理个人结果。

#### 公共内容保存

每份公共说明保存当前语言信息，每种目标语言保留一份当前译文。同一语言再次生成时更新已有译文，中文、英文等结果分别维护。

正文、相关背景、目标语言和翻译规则一致时，用户点击后直接读取已有结果；缺少有效译文时发起生成。已有公共译文仍由用户主动点击查看。

### 译文更新

译文对应生成时的正文、相关背景和翻译规则。系统在说明重新读取或内容更新后检查这些信息，匹配当前内容的结果继续复用。

#### 页面内缓存更新

| 变化 | 处理规则 |
| - | - |
| 诊断消息或注释正文变化 | 自动识别新正文，展示当前原文与对应翻译入口 |
| 报错表达式、相关声明、签名或所需背景变化 | 保留正文语言信息，重新匹配译文 |
| 仅移动行号或修改无关代码 | 复用相同正文和背景的译文 |
| 目标语言或翻译规则变化 | 读取对应结果，缺少有效译文时由用户点击生成 |

内容变化后，用户点击查看当前译文；任务完成时，结果只展示在与其内容一致的说明中。

#### 长期保存结果更新

公共说明的语言信息和译文关联内容版本。库说明随库与文档版本维护；同一库版本内修改说明文字也会更新对应内容。项目描述、操作说明按实际文字变化更新，发布信息保持原值时同样生效。

正文更新后，系统更新当前版本并重新识别语言，已有译文失效。用户点击翻译时生成当前结果，更新该目标语言的已有译文。仅相关背景变化时保留语言信息，重新匹配译文。

不同在用库版本及发布对象分别维护结果。生成期间内容变化时，当前保存结果以最新内容版本为准。

例如操作说明从“按 H 跳跃”改为“按 J 跳跃”，用户看到新原文，点击后查看与新按键一致的译文。

### 使用额度

翻译复用现有配额与限流机制，在 Free / Plus 套餐内独立计量。

| 套餐 | 生成额度 / 24 小时 | 生成尝试上限 / 1 分钟 |
| - | - | - |
| Free | 1000 次 | 30 次 |
| Plus | 5000 次 | 60 次 |

两个窗口分别从首次成功扣额开始计时，后续请求保持原到期时间；到期后恢复额度，下次请求开启新窗口。分钟额度可集中使用。翻译和 Copilot 分开计数，语言分析由系统独立调度与计量。

计数规则如下：

| 操作 | 额度处理 |
| - | - |
| 查看已有目标语言文档或译文 | 直接读取，两个窗口均保持原计数 |
| 返回正在翻译的说明、重复点击同一任务 | 复用任务，维持原计数 |
| 生成一份新译文 | 预扣一次生成额度，并计入短期尝试次数 |
| 修改原文、相关背景或目标语言后请求新译文 | 缺少可复用结果时按新任务计数 |

### 失败处理

翻译失败时保留原文，并提示原因与后续操作。

| 情况 | 处理方式 |
| - | - |
| 24 小时生成额度耗尽 | 提示翻译额度已用完及可用的恢复时间 |
| 1 分钟生成尝试达到上限 | 提示请求过于频繁及可用的等待时间 |
| 模型调用失败、服务端超时或译文无效 | 提示翻译失败，请手动重试 |

额度或频率受限期间，已保存且仍可访问的有效译文继续供用户点击查看。重试时按当前说明重新匹配译文或任务，需要新生成时重新计数。

## User Story

### 理解诊断

用户在一条类型错误上打开 Hover，先阅读原文，再点击“翻译”。译文中的变量名和类型名保持原样，用户可以对照原文理解错误。

等待期间用户去编辑其他文件，任务继续。返回同一诊断时查看任务进度或完成的译文；修改了报错表达式后，看到更新后的诊断，并可点击翻译新内容。

### 阅读库文档

用户查看 Spx 方法时，已有中文说明随中文界面直接展示。查看缺少中文说明的库方法时，点击翻译并对照原文阅读，定义签名和代码示例保持原样。

同一页面会话内返回已点击的说明时复用译文。其他用户读取同一可信版本的公共说明时，先看到原文和翻译入口，点击后直接读取已保存的译文。

### 阅读用户注释

用户查看自定义方法的注释，点击翻译后，译文对应注释正文，并结合该方法的声明和必要背景处理指代。修改注释或相关签名后，再次查看时展示当前原文，点击后读取或生成对应译文。
