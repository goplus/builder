# XBuilder Account hosted interaction

XBuilder Account hosted interaction 是 Account Web 承载的账号交互。它负责登录方式选择、第三方身份首次使用时的账号创建与绑定、初始资料确认、账号选择，以及登录方式的添加与移除。

本文档定义 hosted interaction 的产品与系统边界，描述首期交付的目标状态。账号基础模型见 [XBuilder Account](https://github.com/goplus/builder/blob/acfcce7a61a8052c6663b95931f364912039555f/docs/product/account.zh.md)，自有 app 与 OAuth client 的边界见[自有 app 登记与接入](https://github.com/goplus/builder/blob/acfcce7a61a8052c6663b95931f364912039555f/docs/product/account-app-integration.zh.md)。账号交互行为以本文为准。

## 背景与目标

同一个人可能使用不同的第三方身份登录。首次使用某个身份，不代表这个人还没有 Account 账号。Account 无法从邮箱、用户名、昵称或头像安全地推断账号归属，需要让用户明确选择创建账号，或证明自己控制已有账号后完成绑定。

新增登录方式会持久改变账号的访问能力，移除登录方式则可能影响用户再次登录。Account Web 需要统一承载这些决策，并协调第三方认证、已有登录态、用户确认和 OAuth 授权结果。

目标包括：

- 未绑定的第三方身份在创建或绑定账号前始终经过用户选择
- 创建账号前确认用户名，并允许用户检查和修改初始资料
- 绑定已有账号时重新证明账号控制权，并明确确认绑定
- 当前登录账号与第三方身份所属账号不一致时，由用户选择本次使用的账号
- 用户可以在 Account Web 查看、添加和移除第三方登录方式，但不能自助移除最后一种用户可管理的登录方式
- OAuth 登录与 Account Web 本地操作遵循相同的身份归属和确认规则
- 刷新、返回、重试、并发请求和过期不会重复执行账号变更或 OAuth 授权
- 保留账号创建、身份绑定、身份移除和账号切换的安全审计关联

非目标包括：

- 合并已有账号，或迁移账号拥有的项目、授权及其他产品资源
- 根据第三方展示资料搜索、推荐或自动绑定已有账号
- 将已属于其他账号的第三方身份转移到当前账号
- 普通用户使用用户名和密码注册，或自行设置、重置密码
- 将第三方资料持续同步为 Account 用户资料
- 向自有 app 开放登录方式管理或可定制的身份编排规则

## 核心概念

| 概念 | 含义 |
| - | - |
| `user` | Account 账号主体，以稳定的 `user.id` 引用 |
| `user_identity` | 某个账号与稳定第三方身份之间的绑定 |
| `user_identity_source` | Account 在某个第三方应用上下文中验证身份时取得的应用内标识、展示资料和验证时间 |
| `user_session` | Account Web 使用的登录会话，即 Account session |
| Hosted interaction | 从 Account Web 需要介入开始，到提交唯一结果为止的一次用户交互及其服务端状态 |
| 第三方认证尝试 | 交互发起的一次第三方授权往返，具有独立的一次性回调状态 |
| 控制权证明 | 针对本次敏感操作，通过已有登录方式重新认证后生成的短期证明 |
| 用户可管理的登录方式 | 用户可以在 Account Web 添加或移除的第三方身份绑定，不包含管理员托管密码 |

下文将单个 hosted interaction 简称为交互。一次交互具有固定的来源和用途，成功时确定本次使用的账号，再完成相应的账号操作或 OAuth 授权。

第三方身份以 provider、主体命名空间和稳定主体标识共同确定。已存在有效绑定，或能通过受支持的历史映射解析到已有绑定的身份，属于已绑定身份。经过验证但没有这些绑定的身份，属于未绑定身份。交互中用于登录、创建账号或新增绑定的已验证第三方身份称为待处理身份。

同一个稳定身份可以通过多个第三方应用验证，并具有多条来源记录。这些记录不构成额外登录方式，也不能各自绑定不同的 Account 账号。来源中的第三方应用标识与 Account OAuth client 标识分别属于各自系统。

用户名不作为稳定账号引用。账号关联、Account session、用户 OAuth 令牌主体和用户拥有的产品资源使用 `user.id`。第三方用户名、昵称、头像和邮箱不参与身份匹配。

## 交互来源与用途

交互来源在创建时确定，后续不能更换。

| 来源 | 关联上下文 | 完成后去向 |
| - | - | - |
| OAuth 授权 | 已验证的 OAuth client、所属 app 和 PAR | 本次 PAR 确定的 app 回调地址 |
| Account Web 本地操作 | 服务端允许的本地页面或账号操作 | Account Web 中的固定页面 |

OAuth 来源固定关联一个 OAuth client。`client_id` 是该 client 的对外标识，不是 `app.id`。同一 app 的其他 clients 不能替换授权上下文或消费本次签发的授权码。

交互用途决定允许执行的操作。

| 用途 | 操作目标 |
| - | - |
| 登录 | 根据已有 session、认证结果和用户选择确定本次使用的账号 |
| 添加登录方式 | 固定为发起操作的 Account session 所属账号 |
| 移除登录方式 | 固定为发起操作的 Account session 所属账号及选定的身份绑定 |

添加和移除登录方式只能由有效 Account session 从 Account Web 本地发起。App 的用户访问令牌和 app-only 访问令牌都不能发起这些操作。

用户直接打开 Account Web 且需要登录时，使用本地来源的登录交互，不要求 app 或 PAR。登录后只能进入服务端允许的 Account Web 页面，浏览器不能指定任意返回 URL。

## 登录与账号解析

Account 通过 hosted provider acquisition 在浏览器中取得第三方凭证，也可以通过 provider credential handoff 接收 app 交付的短期凭证。两条路径共享身份验证、归属判断和交互规则。

尚未进入交互时，未提供 provider credential handoff 的 OAuth 请求可以使用有效 Account session 直接完成。Provider credential handoff 取得的身份已绑定且没有 session 冲突时，也可以直接完成 OAuth 授权。需要进入 Account Web 选择登录方式时，后端先创建交互，再由交互发起认证。Provider credential handoff 取得的身份仍需用户决策时，由后端创建交互。交互内的认证始终属于当前交互，不另建交互。

以下 A 表示当前 Account session 所属账号，B 表示第三方身份已绑定的账号。

| 认证结果 | 当前 Account session | 行为 |
| - | - | - |
| 尚未取得认证结果 | 有 A | 可以使用 A 继续，也可以选择其他登录方式 |
| 尚未取得认证结果 | 无 | 选择登录方式 |
| 第三方身份属于 B | 无，或也属于 B | 使用 B 完成登录 |
| 第三方身份属于 B | 属于不同的 A | 进入账号选择 |
| 第三方身份未绑定 | 任意 | 选择创建账号、绑定已有账号或取消 |
| 管理员托管密码验证成功 | 任意 | 使用明确提交凭证的账号完成登录 |

用户名和密码的明确提交已经表达使用该账号的意图，不额外进入账号选择。验证失败时保留当前交互和原 Account session。

未绑定身份必须经过用户决策，无论第三方资料是否完整，也无论系统能否自动生成合法用户名。在最终确认前，不创建 `user`、`user_identity` 或 `user_identity_source`，不创建或替换 Account session，不把账号写入 PAR 作为登录解析结果，也不签发 OAuth 授权码。

当前 Account session 可以提供候选账号，但不能单独授权绑定。没有当前 session 时，不根据第三方资料搜索或建议具体账号，目标由用户通过已有登录方式的成功认证确定。

## 创建账号与初始资料

用户明确选择创建账号后，Account Web 展示资料表单。最终提交同时表示使用这些资料创建账号的确认。

| 字段 | 行为 |
| - | - |
| `username` | 必填。可以建议合法第三方用户名或 Account 生成的中性候选值，由用户确认或修改 |
| `displayName` | 必填、可编辑。优先使用合法第三方昵称，其次使用第三方用户名或用户选择的 Account 用户名 |
| `avatar` | 预览第三方头像或 Account 默认头像，用户可以接受建议或选择默认头像 |

字段沿用 Account 用户资料的格式约束。Account 生成的用户名候选不得编码稳定身份标识，也不得由其派生可关联的公开值。

用户名可用性检查只提供即时反馈，不预留用户名。检查只返回候选值是否可用及字段错误，不返回占用者资料。最终创建时仍以不区分大小写的唯一约束为准。

用户最终提交完整资料时，后端重新检查交互、身份归属和用户名。用户名发生并发冲突时，保留其他资料并要求重新选择，不自动改名，也不绑定到占用该用户名的账号。待处理身份已经被其他请求绑定时，交互失效，不静默改为登录已有账号。

成功创建时，用户、初始身份绑定及本次验证的来源记录一并保存。浏览表单、保存草稿或校验用户名都不会创建这些记录。

第三方资料只作为初始建议。绑定已有账号和后续登录不进入资料补充，也不覆盖已有的 `username`、`displayName` 或 `avatar`。账号创建后，已支持的昵称和头像修改仍由 Account 用户接口负责。

### 头像处理

第三方头像是外部不可信 URL。Account Web 通过后端受控的图片获取或代理能力显示预览，不直接加载该 URL。用户接受头像后，长期头像值必须位于 Account 管理的存储中。

图片获取限制协议、重定向、目标网络、响应大小、媒体类型和解码后尺寸。临时对象具有有效期和清理机制，取消或过期不能留下长期无人关联的头像。

头像获取失败可以重试或改用默认头像。外部图片获取在账号完成事务之外执行，不长期占用数据库锁。

## 绑定已有账号

绑定必须同时取得待绑定身份的认证结果、目标账号的控制权证明，以及用户对两者的明确确认。

用户选择绑定到当前登录账号时，后端在认证前固定该账号。认证结果属于其他账号时，拒绝本次证明。

用户选择绑定其他账号，或没有当前 Account session 时，由成功的已有账号认证确定目标。证明成功后，目标保持不变。登录交互只有显式返回创建或绑定选择，才能清除该目标并重新选择。账号管理发起的添加操作始终以发起账号为目标。

Account Web 在最终确认前展示目标账号的用户名、昵称、头像，以及待绑定身份的 provider 名称和有限展示资料。认证成功本身不表示同意绑定。

最终确认时，后端重新检查目标、待绑定身份和证明。身份仍未绑定时创建绑定，并记录本次验证的来源信息。若并发请求已经将该身份绑定到同一目标，可以按幂等成功完成当前交互，但不重复记录身份新增事件。身份已属于其他账号时，交互失效，不移动绑定或合并账号。

## 账号选择与 Account session

### 已绑定身份与当前账号冲突

第三方身份属于 B、当前 Account session 属于不同的 A 时，用户可以：

- 继续使用 A
- 切换到 B
- 取消整个交互

Account Web 使用账号自身的用户名、昵称和头像区分 A 与 B，并展示取得 B 身份的 provider 名称。不显示内部用户 ID 或稳定第三方标识。

选择 A 时，保留 A 的 session，忽略本次取得的 B 身份。选择 B 时，明确确认切换，再撤销当前浏览器对应的 A session 并创建 B session。A 和 B 的其他 sessions 不受影响。

两种选择都不改变身份绑定。B 已经通过本次第三方认证，因此登录 B 不要求新增登录方式所需的额外控制权证明。

账号管理中的目标账号不能通过这种方式切换。为 A 添加登录方式时取得属于 B 的身份，应拒绝该身份并让用户重新选择，不展示 B 的账号资料。

### 未绑定身份与当前账号

当前登录 A、待处理身份未绑定时，用户仍可以选择绑定到 A、绑定到其他已有账号、创建账号或取消。两种绑定选择都必须重新证明对目标账号的控制权。

选择其他账号或创建账号后，A 的 session 在成功完成前保持有效。最终绑定确认或资料提交前，界面应明确告知当前浏览器将使用哪个账号。启动认证、认证失败、取消、过期或操作失败都不得提前撤销原 session。

### Account session 的处理

| 完成场景 | 当前浏览器的 Account session |
| - | - |
| 明确使用当前 session 继续 | 保留原 session |
| 第三方认证解析到已有账号，当前无 session | 创建该账号的 session |
| 第三方认证解析到当前登录账号 | 可以复用原 session |
| 管理员托管密码登录成功 | 创建新 session。当前浏览器原先已有 session 时，一并撤销原 session |
| 创建账号，或无 session 时绑定已有账号 | 创建所选账号的 session |
| 将身份绑定到当前登录账号 | 成功后轮换当前浏览器的 session |
| 创建、绑定或账号选择导致从 A 切换到 B | 撤销对应的 A session，并创建 B session |
| 添加操作发现身份已经属于当前账号 | 保留原 session |
| 移除登录方式 | 保留当前和其他 Account sessions |
| Provider credential handoff 直接完成 OAuth，未进入交互 | 不创建或替换 Account session |
| 取消、过期、失效或完成事务失败 | 不主动撤销原 session，也不创建替代 session |

成功结果中的 Account session 和用户 OAuth 授权必须属于同一账号。Session 记录与账号操作一并提交，新 session token 只在事务成功后通过响应 cookie 返回。

## Account Web

Account Web 的账号页面展示用户资料和第三方登录方式，并提供添加与移除入口。没有有效 Account session 时，先完成本地登录。

### 查看登录方式

每个有效身份绑定单独展示。同一账号可以绑定同一 provider 的多个不同身份，同一身份的多条来源记录则合并为一个登录方式。管理员托管密码由管理员维护，不作为用户可添加或移除的项目。

身份展示可以使用 provider 名称、来源中的有限展示资料和绑定时间。缺少资料时，以 provider 名称和绑定时间区分。头像遵循前述受控预览规则，不暴露稳定主体、命名空间、第三方应用内标识或内部身份 ID。

### 添加登录方式

用户从账号页面发起添加时，后端固定目标账号和发起操作的确切 Account session，再启动第三方认证。

| 认证结果 | 行为 |
| - | - |
| 身份未绑定 | 证明控制目标账号，再明确确认绑定 |
| 已绑定到目标账号 | 以已经绑定的结果完成，不创建重复绑定或轮换 session |
| 已绑定到其他账号 | 返回归属冲突，重新选择身份，不展示其他账号 |

单次第三方认证取消或发生可恢复错误后，可以重试、选择其他 provider 或取消整个添加操作。原 Account session 和已有身份绑定保持不变。

### 移除登录方式

用户不能自助移除最后一种用户可管理的登录方式。剩余数量按有效第三方身份绑定计算，不包含 Account session、管理员托管密码或身份来源记录。发起操作时先检查剩余数量，最终提交时仍须重新检查。

只有一个第三方身份的用户不能移除它，即使该用户另有密码。只有密码、没有第三方身份的用户可以添加登录方式，但没有可移除项目。

管理员托管密码、待移除身份本身或其他已绑定身份都可以用于控制权证明，证明方法不改变剩余数量的计算规则。

1. 用户选择身份 X，后端固定目标账号、X 和发起操作的 Account session。
2. 用户证明控制该账号，Account Web 展示 X 和移除后仍保留的第三方登录方式。
3. 用户确认后，后端重新检查归属、session、证明和剩余绑定数量，原子删除 X 及其来源记录并完成交互。

最终检查发现 X 已不存在、归属变化或移除后没有其他第三方绑定时，交互失效，不删除任何身份，也不记录成功移除事件。并发移除同一个身份时只有一个成功，并发移除仅剩的两个身份时最多一个成功。

管理员仍可特权移除全部第三方身份，不受用户自助移除的数量限制。所有影响身份绑定数量的入口都必须使用一致的账号级并发约束，包括管理员操作和历史绑定规范化，不能使自助移除绕过最终检查。

解绑只影响该身份今后的登录。Account session 与用户授权关联 `user.id`，用户令牌通过授权关联账号，不依赖原登录身份。因此解绑不轮换或撤销 Account session，不撤销 OAuth grant 或令牌，也不影响 app 自己的 session。需要结束已有 Account session 时，使用独立的 session 管理操作。

X 移除后再次用于登录时，按未绑定身份进入创建或绑定选择。来源记录和历史映射不得恢复已经移除的登录方式。

### 页面状态

交互页面根据后端返回的状态展示登录方式选择、账号创建与绑定、资料表单、控制权验证、最终确认和账号选择。页面只使用交互入口定位状态，URL 参数不决定步骤或操作目标。

刷新和浏览器后退都重新读取服务端状态。返回前一步必须提交允许的返回动作，旧页面不能恢复旧证明或覆盖较新的选择。成功、取消、过期、失效和失败分别展示对应结果或继续 OAuth 回调。

`ui_locales` 与本地语言选择只影响界面语言。交互可以保留已协商的语言，但它不参与身份归属、控制权证明或授权判断。

原生 app 使用系统浏览器或系统认证会话打开 Account Web。受限运行环境通过 provider credential handoff 提供身份后，如需用户决策，也必须进入 Account Web。

## 控制权证明

绑定或移除登录方式都要求[针对当前操作重新认证](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#require-re-authentication-for-sensitive-features)。普通 Account session 即使刚创建，也不能代替本次控制权证明。

### 认证方式

控制权证明使用目标账号已有的登录方式：

- 通过当前已启用的 provider，重新认证已绑定到目标账号的第三方身份
- 验证管理员托管的密码凭证

第三方认证必须由当前交互启动新的授权往返。系统按 provider 能力请求重新认证或账号选择，例如 OpenID Connect（OIDC）的 [`prompt=login` 和 `prompt=select_account`](https://openid.net/specs/openid-connect-core-1_0.html#AuthRequest)。第三方服务可以复用自己的 SSO session，Account 不承诺每次都会重新要求输入密码。

绑定操作中，待绑定身份本身和其他未绑定身份都不能证明已有账号。可以使用同一 provider 下另一个已绑定的稳定身份。App 交付的 provider credential handoff 不能用于控制权证明。

控制权验证只解析已有账号，不替换待处理身份、切换 Account session 或完成 OAuth 授权，也不转入账号创建或绑定流程。未能解析到已有账号时，本次认证失败，用户可以换一种已有登录方式。

目标账号已确定时，用户只提交密码，由后端验证该账号的密码凭证。尚未确定目标时，用户提交用户名和密码，由后端解析已有账号。

认证失败不区分用户名不存在、未设置密码、密码错误或第三方身份未绑定，不返回未认证目标的资料。已经由当前 Account session 或本次成功认证确认的账号，可以展示必要的账号资料。

目标账号没有可用登录方式时，本交互不能完成操作，用户需要管理员协助。

### 证明的范围与失效

控制权证明绑定当前交互、来源、用途、目标账号和用于认证的凭证。绑定操作还关联待绑定身份，移除操作则关联固定的待移除身份。

证明具有独立的短期有效期，不晚于交互的固定过期时间，并在成功完成操作时原子消费一次。不能复用于其他交互、其他身份或其他操作。

最终确认时，证明所依据的身份绑定或密码凭证必须仍有效且属于同一目标。密码被替换或清除、身份绑定被移除或改变归属时，已有证明失效。

如果只有证明到期或认证凭证失效，且目标、身份归属和 session 等其他前提仍成立，清除旧证明并返回控制权验证，保留原目标。移除操作若不再满足剩余登录方式约束，交互失效，不能通过重新证明恢复。其他不可恢复的归属或上下文变化也使交互失效。

## 交互状态与生命周期

交互的来源、用途和操作目标由后端保存。浏览器提交当前允许的用户动作和输入，后端决定下一步。

| 类别 | 保存内容 |
| - | - |
| 来源与完成目标 | OAuth client、所属 app、独占的 PAR 与已验证回调，或固定的本地页面 |
| 操作上下文 | 创建时的 Account session 引用、已固定的目标账号与待移除身份 |
| 浏览器绑定 | 与 Account session 分离的流程连续性 |
| 待处理身份 | 稳定身份键、已有绑定引用、验证时间，以及本次第三方应用与来源标识 |
| 展示与输入 | 有界的第三方资料、初始建议和不具有授权效力的资料草稿 |
| 当前进度 | 步骤、版本、固定过期时间和有效的认证尝试 |
| 控制权证明 | 目标账号、认证凭证引用、操作范围和独立过期时间 |
| 完成结果 | 唯一终态、原因类别、成功使用的账号及完成时间 |

稳定身份键、内部绑定引用和来源标识只用于服务端的归属检查、身份绑定和来源记录保存，不返回给浏览器。稳定第三方标识和来源应用内标识也不写入普通日志。展示资料只保留必要的第三方用户名、昵称和头像信息，不保存完整响应、邮箱或无关令牌声明。

交互保存可恢复的多步骤状态。`auth_flow` 继续表示 PAR、第三方回调状态和授权码等短期协议产物，不能以消费一个一次性凭证代替整个交互的生命周期。

### 状态与步骤

| 状态 | 含义 |
| - | - |
| `active` | 可以执行当前步骤允许的动作 |
| `completed` | 已提交成功结果 |
| `cancelled` | 用户明确取消整个交互 |
| `expired` | 已到固定过期时间 |
| `invalidated` | 身份归属、session 或其他安全前提发生不可恢复变化 |
| `failed` | 不可恢复的服务或协议错误使本次交互无法继续 |

除 `active` 外均为终态。终态结果不可改变，也不能恢复为活动交互。

| 步骤 | 进入条件与主要动作 |
| - | - |
| `acquireIdentity` | 登录可以使用当前 session、第三方或密码认证，添加操作只取得新的第三方身份 |
| `chooseResolution` | 登录使用未绑定身份，选择创建账号、绑定已有账号或取消 |
| `completeProfile` | 用户选择创建账号，编辑并最终提交初始资料 |
| `proveAccountControl` | 绑定或移除身份前，通过已有登录方式证明账号控制权 |
| `confirmLink` | 已有有效证明，检查目标账号与待绑定身份并确认 |
| `confirmUnlink` | 已有有效证明，检查目标账号与待移除身份并确认 |
| `selectAccount` | 当前 session 与已绑定身份属于不同账号，选择本次使用的账号 |

登录交互可以在 `acquireIdentity`、`chooseResolution` 或 `selectAccount` 开始，取决于创建时已经验证的事实。添加操作从 `acquireIdentity` 开始，移除操作固定身份后从 `proveAccountControl` 开始。

资料提交、绑定确认、移除确认和账号选择满足全部约束后进入 `completed`。在 `acquireIdentity` 明确使用有效当前 session、密码登录成功，或取得没有 session 冲突的已绑定身份时，也可以直接完成登录。

可恢复的字段错误、用户名冲突、认证失败或单次第三方取消保留当前交互。只有证明失效时按前述规则返回 `proveAccountControl`，其他不可恢复的前提变化进入 `invalidated`。

### 返回与重新选择

| 用途与当前步骤 | 允许的返回 |
| - | - |
| 登录的 `chooseResolution` 或 `selectAccount` | 返回 `acquireIdentity`，重新选择登录方式 |
| 登录的 `completeProfile`、`proveAccountControl` 或 `confirmLink` | 返回 `chooseResolution`，重新选择创建或绑定 |
| 添加操作的 `proveAccountControl` | 返回 `acquireIdentity`，重新取得待添加身份 |
| 添加操作的 `confirmLink` | 返回 `proveAccountControl` |
| 移除操作的 `confirmUnlink` | 返回 `proveAccountControl` |

交互同一时刻最多持有一个待处理身份。返回 `acquireIdentity` 时，失效旧认证尝试及其未应用结果，清除待处理身份、相关证明、资料建议和草稿，以及不是由用途固定的目标账号。

返回 `chooseResolution` 时可以保留同一身份的资料草稿，但清除证明和本次选择的目标账号。返回控制权验证时保留操作目标并失效旧证明。所有离开认证步骤的返回动作也必须失效尚未应用的认证结果。

### 第三方认证尝试

每次尝试绑定交互、provider、用途、预期步骤、启动后的交互版本和过期时间。同一交互最多有一个有效尝试，包括等待回调和已有结果但尚未应用的尝试。启动新尝试会失效旧尝试及其结果，并推进交互版本。

回调必须匹配尝试绑定的 provider，并先原子消费一次性回调状态，再验证第三方凭证。取消、错误和验证失败都不能复用该状态。外部验证在持有交互完成锁的事务之外进行，短期结果保存到所属尝试。

成功结果包含已验证身份与有限来源资料，失败结果只包含有界错误类别。若凭证已经消费但结果未能保存，重试必须取得新凭证。

回调不读取 Account session 或浏览器绑定 cookie。它只保存结果，再以 `303` 返回服务端为本次尝试确定的 Account Web 地址。第三方或浏览器不能覆盖该地址，也不能以 provider state 代替交互入口。

Account Web 随后发送同源恢复请求，由后端校验浏览器绑定、当前 session、步骤、版本和过期时间，再应用结果并结束本次尝试。认证成功时，后端根据用途和当前步骤推进交互或完成登录。取消和可恢复错误保留当前步骤。迟到、过期和已消费结果不能再次推进交互。

密码登录和密码控制权验证在交互动作中同步完成，不创建独立的第三方认证尝试。验证失败只拒绝本次提交，不改变原 session 或待处理身份。

### 浏览器绑定与 PAR

交互入口使用高熵、不透明的 handle，服务端使用其哈希校验和查找。Handle 不承载浏览器可以修改的账号、步骤或授权状态。

读取或操作交互还要求匹配的浏览器绑定 cookie。该 cookie 独立于 Account session，使用 `__Host-` 前缀、`HttpOnly`、`Secure`、`SameSite=Lax` 和 `Path=/`，不设置 `Domain`。Cookie 值使用独立的高熵随机值，不编码用户、session 或交互状态，服务端保存哈希或带密钥摘要。

创建交互时，服务端在返回 handle 或跳转前建立浏览器绑定。同一个浏览器绑定可以关联多个独立交互，每个 handle 只访问对应交互。只有 handle 而没有匹配 cookie 时，不返回交互详情，也不重新绑定。IP 地址和 User-Agent 不能替代这种绑定。

一个有效 PAR 最多关联一个独占的交互，关联必须在 `request_uri` 有效时建立。相同浏览器重复进入同一 PAR 时恢复原来的活动交互，不能创建竞争流程。不匹配的浏览器不能读取原 handle 或重新占用 PAR。这一约束遵循 [PAR 的一次性授权请求边界](https://www.rfc-editor.org/rfc/rfc9126.html#section-4)。

在有效期内完成关联的授权请求，可以通过交互入口持续到交互的固定过期时间。原 `request_uri` 的有效期不延长，过期后不能再通过 authorize 恢复或发起授权。交互进入终态时，关联的 PAR 一并消费或永久关闭。

### 上下文校验与并发

交互创建时记录当前浏览器携带的确切 Account session，没有 session 也作为一项前提。读取活动交互时校验这一前提，不匹配时拒绝返回详情，不执行状态转换。

状态变更请求发现原 session 消失、失效、被替换，或原本没有 session 却出现新 session 时，将活动交互置为 `invalidated`。即使新 session 属于同一账号，也不能依据旧页面撤销或替换它。失效不会主动改变浏览器现在持有的 session。

完成时重新检查身份绑定、目标账号、证明凭证和原始授权上下文。稳定身份键的唯一约束保证同一身份只能属于一个账号。同一目标的并发绑定和证明失效属于前文允许的恢复情况，其他归属变化不能静默替换账号候选或操作目标。

后端处理交互动作或保存资料草稿时，必须检查交互状态、当前步骤、版本和过期时间，只执行当前步骤允许的操作。同一版本只允许一次状态变更成功。版本过期但权威事实未变化时，返回最新状态供界面刷新，不能覆盖较新的选择。

交互成功完成时，后端在同一事务中确定本次使用的账号、保存完成结果，并提交适用的用户、身份及来源记录变更、证明消费、session 变更、必需审计事件或其可靠投递记录，以及 OAuth 的 PAR 关闭和授权码签发。

确认、取消、恢复第三方认证结果和重试并发时，交互只能提交一个终态。重复请求可以观察已提交结果，不能重复执行账号变更、session 切换、成功审计或授权码签发。

### 过期与清理

交互创建时确定固定过期时间。刷新、修改资料或启动新尝试都不延后它。认证尝试和证明各自具有更短的有效期，不晚于交互过期时间。具体时长由服务端控制。

到期立即禁止活动动作，不依赖后台清理是否已经执行。`GET` 查询只返回计算出的过期状态，不写入状态。后续状态变更请求或过期任务负责原子保存 `expired` 结果并关闭 PAR。

OAuth 来源的过期页面可以提供发送错误结果的动作。该动作只持久化和发送已经确定的结果，不能恢复交互。

终态记录在短期结果保留窗口后清理。不再需要的稳定第三方标识、来源标识、展示资料、草稿和临时头像引用应尽快清除。长期审计依赖内部账号、身份、session 和不可重放的关联标识。

## OAuth 接续与错误

OAuth 来源只有在 client、所属 app、PAR、PKCE、授权范围和回调地址通过校验后才能建立。回调地址按 client 的注册配置和受控预览规则验证，交互保存本次已验证的确切地址，浏览器不能覆盖。

完成前重新检查 app 和 client 状态、授权方式，以及适用的回调和授权范围策略。App 或 client 停用时，关联的未完成交互和 PAR 永久失效，重新启用不会恢复它们。

账号交互只确定本次使用的用户，不扩大原授权范围，也不替代 app 用户授权规则。PAR、回调地址、PKCE 和授权码始终绑定同一个 OAuth client。

### 错误去向

字段校验、用户名冲突、控制权验证失败、单次第三方取消、可恢复的上游故障和版本冲突留在 Account Web。它们不会自行变成用户拒绝 app 授权。

有可信回调的 OAuth 交互按 [OAuth 授权响应](https://www.rfc-editor.org/rfc/rfc6749.html#section-4.1.2)返回终态结果，均携带 PAR 中原始 app `state`：

| 结果 | App 回调 |
| - | - |
| 成功 | `code` |
| 用户取消整个交互 | `error=access_denied` |
| 策略或安全决策拒绝授权 | `error=access_denied` |
| 交互过期 | `error=invalid_request` |
| 临时服务故障使本次交互无法继续 | `error=temporarily_unavailable` |
| 不可恢复的内部错误 | `error=server_error` |

缺失或无效 client、未验证的回调地址、未被有效交互接入的过期 PAR，以及无法再确认回调可信性的请求，停留在 Account 接口或 Account Web 错误页面，不跳转到浏览器提供的地址。

第三方返回的 `access_denied` 只取消本次上游认证。用户仍可重试、换登录方式或明确取消整个交互。第三方原始错误、账号归属细节和内部诊断不复制到 app 回调。`error_description` 如需返回，只包含稳定、通用的说明。

成功响应不能带 `error`，错误响应不能带 `code`。Provider state、交互 handle 和证明引用不能替代 app `state`。

本地来源没有 app 回调。成功、取消、过期、失效和失败都返回固定的 Account Web 页面。

### 完成与结果传递

OAuth 交互通过 Account Web 的页面级 `POST` 完成最终动作。后端提交完成结果后，以 `303` 返回可信 app 回调。授权码只通过该授权响应传递，不进入交互状态响应或普通 JSON 数据。

页面级 `POST` 遇到可恢复错误时，以 `303` 返回对应 Account Web 页面。终态错误先保存结果并关闭 PAR，再返回 app。结果发送只是已提交结果的传递，不产生另一次账号操作。

服务端不保留授权码原值供刷新后重发。成功回调丢失时，app 重新发起 OAuth 授权，原交互不能签发第二个授权码。错误结果可以重发，但结果本身不能改变。

App 回调处理同时支持成功与错误，对两者验证 `state`。错误不执行令牌交换，并清理对应的 PKCE 待处理状态。自有 Web app 在处理后清除地址栏中的回调参数，避免 `code` 和 `state` 原值留在页面导航中。

## API 边界

完整请求、响应、字段约束和错误契约应在 [OpenAPI](https://github.com/goplus/builder/blob/acfcce7a61a8052c6663b95931f364912039555f/docs/openapi.yaml) 中定义，并随实现与前端接入同步更新。

Account Web 使用 `account.xbuilder.com/api/*` 作为同源接入层，转发到 `api.xbuilder.com/account/*`。浏览器授权从 Account Web 的 `GET /api/oauth/authorize` 进入，由浏览器携带该域的 host-only Account session cookie 和浏览器绑定 cookie。App 的 OAuth facade 可以将浏览器重定向到该入口，不能在 app 后端代理最终浏览器授权响应。

### Account OAuth endpoints

```http
POST /account/oauth/par
GET  /account/oauth/authorize
```

- PAR 可以接收 provider credential handoff，保存已经验证的身份，不提前为未绑定身份创建账号
- Authorize 校验 PAR 后直接完成安全可确定的授权，或独占 PAR、建立浏览器绑定并创建交互

### Hosted interaction endpoints

```http
POST /account/interactions
GET  /account/interactions/{interaction}
POST /account/interactions/{interaction}/actions
PUT  /account/interactions/{interaction}/profile-draft
```

- 创建接口只创建本地来源的交互，登录可以匿名发起，添加和移除要求有效 Account session。创建成功后返回交互 handle 和初始状态。OAuth 来源由 authorize 根据已验证 PAR 创建
- 移除操作接受当前身份列表中的不透明引用，由后端在发起账号的有效绑定中解析并固定，不接受目标用户 ID 或稳定第三方标识
- 查询返回后端计算的交互状态，包括状态、步骤、版本、过期时间、允许的动作和当前步骤所需的展示资料
- 动作接口提交有类型的用户动作、允许的输入和当前版本，涵盖使用当前 session、启动或恢复第三方认证、密码验证、创建或绑定选择、最终确认、账号选择、返回和取消
- 资料草稿以完整目标值和当前版本幂等保存，返回字段校验、用户名可用性和更新后的状态，不代替最终资料提交
- 保存草稿推进版本，过期版本不能覆盖新草稿。当前步骤仍允许保存且草稿已经等于目标值时，可以返回当前状态作为幂等结果
- 最终资料动作提交完整资料，绑定与移除动作重新验证证明和归属，账号选择只接受服务端提供的候选
- 启动或恢复第三方认证、OAuth 最终完成和其他页面跳转动作由 Account Web 以支持表单编码的页面级 `POST` 提交，后端使用 `303` 跳转，不用 `fetch` 跟随跨源响应
- 保留在页面内的动作返回最新交互状态，终态错误的发送动作只传递不可变结果，不签发授权码或恢复交互

交互状态可以包含 OAuth 来源的 app 展示资料或本地操作名称、当前步骤允许的 providers、由当前 session 或认证确认的候选账号、已证明目标、待处理身份与待移除身份的有限展示资料、初始建议、草稿和有界错误。不返回稳定第三方标识、来源应用内标识、内部用户 ID、PAR 内容、回调地址、app state、provider state、证明凭证、session token 或其他认证凭证。

来源、用途、步骤、待处理身份、操作目标和本次使用的账号均由后端确定。浏览器不能提交下一步骤或以任意用户 ID 选择账号。

### Account identity provider callback endpoints

```http
GET  /account/identity-providers/{provider}/callback
POST /account/identity-providers/{provider}/callback
```

- 保持 provider 配置中的固定回调地址，并支持其需要的 `GET` 或 `POST` 方式
- Provider state 唯一定位交互、尝试、用途、步骤与版本
- 消费回调状态并保存验证结果后返回 Account Web，不创建用户、绑定身份、替换 session 或完成 OAuth 授权
- 结果只由匹配浏览器的恢复动作应用

### Current account endpoints

```http
GET /account/user/identities
```

- 以身份绑定为单位返回不透明引用、绑定时间和必要展示资料，展示资料可以来自该身份最近验证的来源
- 不返回稳定主体、命名空间、来源标识、内部身份 ID 或原始第三方头像 URL
- 只接受 Account session，用户令牌和 app-only 令牌都不能读取登录方式
- 添加和移除由交互完成，不提供可绕过证明与确认的直接变更入口

## 安全与审计

### 请求与浏览器边界

交互 handle、Account session、OAuth 令牌和浏览器绑定不能互相替代。读取交互要求 handle 和浏览器绑定，账号管理操作还校验发起操作的 session，绑定或移除身份另外要求控制权证明和用户确认。

Account Web 发起的创建、草稿保存和所有变更动作校验允许的 `Origin` 或使用等价 CSRF 防护，匿名登录交互也不例外。协议入口以外的 `GET` 只读取状态。第三方回调使用单次 provider state 防护。

敏感页面使用 CSP `frame-ancestors 'none'` 禁止嵌入。交互、登录方式管理及 app 回调页面、身份列表、变更响应和协议跳转使用 `Cache-Control: no-store`，携带交互或回调上下文的页面与响应使用 `Referrer-Policy: no-referrer`。重定向与敏感参数处理遵循 [OAuth 安全最佳实践](https://www.rfc-editor.org/rfc/rfc9700.html)。

密码认证、交互创建、认证尝试和用户名检查分别执行限流与滥用检测。

### 敏感数据

原始第三方凭证只用于即时验证，不保存到交互或身份来源记录。Account 授权码的校验信息保存在独立的一次性协议状态中，交互不保存授权码原值。

交互 handle、浏览器绑定值、PAR 引用、app state、provider state、密码及其派生值、授权码、令牌和 client secret 不进入普通日志、访问日志、分析工具或第三方前端监控。回调查询参数、相关路径、请求正文及响应 `Location` 按字段脱敏。

第三方资料按不可信输入转义并限制长度，原始响应和未过滤错误不进入状态响应或审计。

### 审计与安全事件

账号变更沿用平台的审计能力，至少记录以下成功结果：

- 创建账号与初始身份绑定
- 新增身份绑定
- 移除身份绑定
- 用户明确选择后切换当前浏览器的账号

审计事件分别记录目标账号、完成后使用的账号和受影响的身份，并关联交互及其来源、用途以及适用的 app、OAuth client 和 session。交互发起时已有 Account session 的，还应单独记录该 session 所属账号。

绑定与移除事件必须能追溯到授权该操作的控制权证明，但不记录凭证值。绑定导致的同账号 session 轮换也记录在该变更事件中，不必单独产生持久审计事件。

必需审计记录与成功变更原子保存，或在同一事务中保存可靠投递记录。不能先报告成功再尽力补写。幂等恢复不重复产生同一成功变更事件。

控制权验证的成功与失败、其他认证失败、重放、用途不匹配、试图改变固定目标或归属冲突属于安全监控事件。普通字段错误、用户名冲突、返回、过期、放弃和暂时的第三方故障默认只进入诊断或指标，不作为持久安全变更记录。监控事件投递失败不能使被拒绝的认证或授权变为成功。

审计只记录各类事件明确定义的字段和有界类别，不保存原始第三方主体、来源标识、完整资料、临时头像位置或未过滤异常。调查使用不可重放的内部关联标识。IP 地址和 User-Agent 属于个人数据与弱信号，其访问和保留按明确策略管理。

## 首期交付范围

首期交付本文定义的登录和登录方式管理能力，覆盖 OAuth 与 Account Web 本地来源。

下列能力不在首期交付范围内：

- 账号恢复
- 已有账号的用户名自助修改
- 创建账号时上传自定义头像
- 用户可见的账号活动记录
- 风险评分、设备信任或多因素认证策略

## 现有账号与接入

已有身份绑定继续有效，受支持的历史映射可以解析到原账号。历史规范化只迁移仍存在的绑定，不能恢复已解绑的身份。引入交互不要求批量迁移现有绑定，也不追溯识别、合并或重新分配历史账号。

独立的 `GET /account/identity-providers`、`GET /account/identity-providers/{provider}/authorize` 和 `POST /account/session` 登录入口在接入迁移完成后移除。可用 provider 由交互状态返回，第三方授权和密码登录由交互动作发起。Session 查询、退出和管理接口保持各自职责。
