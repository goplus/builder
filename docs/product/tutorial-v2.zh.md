# 用户教程 User Tutorial（新课程体系）

> 本文档是对[现有 User Tutorial 设计](./tutorial.zh.md)的修订与扩展：现有的 Copilot 驱动引导方案保留为两种课程形态之一（引导式课程 Guided Course），本文档新增目标式课程（Playground Course）形态。

## 背景

现有 User Tutorial 以 Copilot 为核心：课程即 Prompt（Markdown-as-course），由 Copilot 逐步引导用户完成操作。这个方案同时服务两个诉求：

1. Builder 作为 IDE 的使用引导（Product Tour）
2. （基于游戏的）编程教育

课程实践中我们发现，对诉求 2 而言，"按步骤引导"存在固有不足：

* **学习者不需要思考。** 引导式课程把任务拆解为逐条指令，学习者只是执行指令："点这里"、"把这行改成那样"，甚至可以直接复制或一键应用答案代码。指令执行得再顺利，也不构成对概念的理解，更谈不上迁移运用。
* **没有探索空间。** 路径唯一、每一步偏离都会被纠正。学习者没有机会试错，而"试错—观察—修正"正是编程学习的核心循环，也是乐趣所在。
* **过度依赖 LLM。** 每一步推进都需要 LLM 参与，带来成本、延迟与不确定性。课程体验取决于模型每一次的临场发挥，创作者无法精确控制节奏与判定，同一门课程两次体验可能差别很大。

结论是**两类教学场景需要两种课程形态**：

* 产品操作类教学（非 Coding）：操作路径本来就唯一，按步骤引导是正确形态 → **引导式课程 Guided Course**
* 编程教学（Coding）：需要思考与探索，应当给目标、不给步骤 → **目标式课程 Playground Course**

## 两种课程形态

|  | 引导式课程 Guided Course | 目标式课程 Playground Course |
| --- | --- | --- |
| 驱动方式 | Copilot 按 Prompt 逐步引导 | 课程代码驱动 |
| 教学对象 | Builder 的 UI 操作 | 课程项目（一个可改造的游戏世界） |
| 场所 | 不绑定——整个 Builder 都是舞台 | 项目编辑器 |
| 学习者做什么 | 跟随指令操作 | 在预置场景中自行探索、达成目标 |
| 通过判定 | Copilot 判断（游戏退出信号辅助） | 课程代码判定（运行时信号、代码检查、LLM completion） |
| LLM 依赖 | 强（每步参与） | 弱（课程代码按需调用） |
| 典型场景 | 产品使用教学、资源操作 | 编程概念教学 |
| 创作产物 | Prompt | 课程代码 + 课程项目 + 课程素材 |

两种形态面向的场景不同，但选择权在课程创作者：理论上也可以用引导式形态制作 Coding 课程（例如手把手完成第一行代码）。

两种形态在机制上分开支持，不做统一抽象。

## 基本概念

### 课程 Course 与课程系列 Course Series

Course 仍是核心教学单元，由三部分构成：**元数据 + 形态 + 内容**。

* **元数据**：Title、Thumbnail 等，沿用现有设计
* **形态 Type**：引导式 / 目标式，决定内容的形式与课程的驱动方式
* **内容**：引导式课程为 Prompt（Markdown-as-course）+ 入口 URL；目标式课程为课程数据（课程代码 + 课程项目 + 课程素材）

两种形态的本质差异：**引导式课程教的是"操作 Builder"，对象是 UI，因此不绑定场所——首页、编辑器、社区页都可以是课程的舞台；目标式课程教的是"改造一个世界"，对象是课程项目，因此总是在项目编辑器中进行**。

一个容易混淆的边界：形态之分在于"谁驱动流程"，不在于"是否用到 LLM"。目标式课程同样可以调用 LLM 能力（判定表达类目标、生成个性化反馈），它仍是目标式课程——流程（开场、运行、完成）全部由课程代码驱动。

Course Series 将一组 Course 组织为有序系列，承载课程顺序与"下一课"推进。同一系列内的课程形态保持一致，暂不支持混排。

Course Gallery、Course Admin 沿用现有设计。

### 目标式课程 Playground Course

每节目标式课程一定关联一个项目，进入课程即进入项目编辑器。课程的一切行为由**课程代码**表达与驱动，不设独立的声明式配置层。

#### 课程数据

* **课程代码**：基于 class framework 编写，调用框架提供的原子能力（见下）编排课程的全部流程——开场、判定、完成。常见课程只是对这些能力的少量直接调用；复杂课程可以编写任意的编排与判定逻辑。
* **课程项目**：创作者预先构建的游戏项目——舞台、精灵与场景代码。项目是课程数据的一部分，不独立保存、不发布。场景代码承担两件事：构成一个有趣、可探索的世界（学习者的改动在其中产生可见反馈）；在关键事件发生时输出完成信号（特定日志），供课程代码判定。
* **课程素材**：课程引用的讲解视频等素材，同样是课程数据的一部分。（未来可能提供公共素材库，供多门课程复用同一素材。）

学习者对课程项目的修改仅存在于本次学习中，不影响课程本身与其他学习者；学习者可将成果保存为自己的项目。

#### 原子能力

框架向课程代码提供以下原子能力，课程按需调用、自由组合：

* **消息展示**：以对话框向学习者展示文字（支持 Markdown）、播放视频、以 spotlight 高亮界面元素并附提示；每次展示可等待学习者确认后继续，也可自动推进
* **运行时信号**：监听游戏运行日志。这是判定的主通道：只要程序在运行，就总能用 `println` 向控制台输出内容——场景代码在关键事件发生时输出特定日志，课程代码等待这些信号，即可感知学习者"做到了什么"
* **代码检查**：确定性地检查学习者代码中是否出现指定写法，感知学习者"用什么方式做到"
* **LLM completion**：向 LLM 发起一次生成请求并取回结果，自动携带课程信息、XGo/spx 知识等上下文（这类请求不出现在学习者与 Copilot 的对话中）。可用于判定"表达类"目标（如让角色说一句打招呼的话，说什么都对），或基于学习者的实际代码生成个性化反馈
* **完成**：`complete` / `completeWith <一句话反馈>` 结束课程并展示完成弹窗，学习者可进入下一课或返回课程列表

判定的原则：**使用代码判定结构化的结果**。课程场景的状态转移应收敛到唯一、确定的最终状态——"完成"对应一个确定的状态，程序才能检查它；LLM completion 用于结构化判定覆盖不了的表达类目标与反馈生成。

#### 编辑器能力

课程可以按需启用的编辑器定制，相互独立、可自由组合：

* **simple（简单）模式**：面向单精灵编程的聚焦形态——隐藏精灵列表、禁用精灵设置；精灵名字呈现在舞台上，悬停精灵浮现名字标签、点击即把名字插入代码，学习者不必拼写精灵名；放大代码字号；运行按钮与 Copilot 入口居中；更大的 API Reference。运行态不自动退出，由学习者自行切换，鼓励反复"改一点、跑一下"
* **API 白名单**：过滤 API Reference，只显示本课相关的 API、隐藏无关分类，减小认知负担
* **标尺 Ruler**：舞台上的度量教具，帮助学习者建立坐标与距离的直觉

### 引导式课程 Guided Course

沿用[现有设计](./tutorial.zh.md)：课程即 Prompt，Copilot 驱动逐步引导，主动感知用户操作与 Builder 事件（个别难以感知的事件以"继续"按钮辅助），游戏退出信号辅助判定。修订点：

* 优化判定通过后的输出：通过即收束，不再继续引导
* "学习者忘记退出课程、Copilot 持续感知与对话"的问题不做系统性解决：以现有的偏离感知为主，可叠加时间限制（到期提醒）

### Copilot 的角色

两种形态中 Copilot 的定位不同：

|  | 引导式课程 | 目标式课程 |
| --- | --- | --- |
| 定位 | 驱动者：主动逐步引导 | 助手：被动待命 |
| 触发 | 进入课程即开始并持续推进 | 学习者主动求助 |
| 职责 | 高亮 UI、感知事件、判定通过 | 答疑；并为课程代码提供 LLM completion 能力 |

目标式课程中，Copilot 的答疑不应替学习者完成任务：课程内禁用回复中代码块的复制与一键应用（code-block copy / code-change apply），避免学习者绕过思考、直接套用答案。

## User Story

### 学习者：完成目标式课程「点选目标」

* 学习者进入课程，编辑器以 simple 模式打开课程项目：舞台上有 Lita 和一颗蘑菇
* 开场依次进行：对话框交代任务（"让 Lita 走到蘑菇那里"）→ 播放 `stepTo` 讲解视频
* 学习者自行尝试。第一次用 `step 200` 试探，运行后发现 Lita 走过头了；改成 `step 150`，凑近了但没对准
* 学习者运行成功（场景代码检测到 Lita 碰到蘑菇，输出完成信号），但代码中没有使用本课要求的 `stepTo`——课程提示再试一次："试试点击舞台上的蘑菇，让 Lita 一步走到它面前"
* 学习者悬停舞台上的蘑菇，点击浮现的名字标签把 `Mushroom` 插入代码，写出 `stepTo Mushroom`，运行通过
* 完成弹窗出现，展示课程基于其最终代码生成的一句话反馈："你用 stepTo 让 Lita 直接走到了蘑菇面前。"学习者进入下一课或返回课程列表

期间学习者随时可以唤起 Copilot 提问；Copilot 答疑，但不主动介入，也不直接给出可套用的答案。

### 创作者：制作目标式课程「点选目标」

* 构建课程项目：放置 Lita 与蘑菇，在蘑菇的场景代码中检测被碰到并 `println` 完成信号
* 编写课程代码，调用原子能力编排流程：

	- 开场：展示任务说明，播放 `stepTo` 讲解视频（课程素材）
	- 等待完成信号；收到后检查学习者代码是否使用了 `stepTo`——未使用则提示再试一次，使用了则生成反馈并完成：

		```
		word := llm.getCompletion("用一句话点评这份代码做成了什么：...")
		completeWith word
		```

	- 启用编辑器能力：simple 模式；API 白名单只显示 `stepTo` 及此前已学的 API
* 在 Course Editor 中预览，以学习者视角试运行整个流程
* 测试通过后发布，加入所属 Course Series

### 学习者：完成引导式课程「创建 Project」

与[现有文档的 User Story](./tutorial.zh.md#user-story) 一致：Copilot 逐步引导找到入口、高亮 UI 元素、完成创建后收束会话。

## 课程创作

* **Course Editor**：课程与课程系列的编辑入口。目标式课程编辑课程数据（课程项目、课程代码、课程素材），引导式课程编辑 Prompt；系列层面管理课程顺序与元数据
* **Course Preview**：以学习者身份试运行真实的课程流程（而非另做一套模拟），支持单课预览与整系列走查；预览中的修改不写回课程数据
* 课程数据支持导出与导入，适配本地编辑等不同创作工作流
