# 通用翻译 Translation

XBuilder 将代码编辑器中语言服务提供的代码诊断说明和文档说明翻译成用户选择的语言并展示。

## 背景

非英文用户查看代码时，诊断和文档说明仍可能以英文呈现。现有基于原文匹配的诊断翻译难以覆盖随代码变化的内容。本设计改由 builder 使用 AI 翻译语言服务返回的英文原文。

## 目标

* 让非英文用户以所选语言阅读诊断说明和文档说明。
* 同一套翻译能力可以处理多种语言服务内容，仅为每类消息维护少量翻译规则。
* 翻译不可用时仍能查看原文，不阻断代码编辑器的使用。

## 范围

本次覆盖代码编辑器悬浮提示（Hover）中的两类语言服务内容：诊断说明，以及类型、方法等定义的文档说明。两者均以英文原文为基础，仅在用户选择非英文语言时翻译。目前 XBuilder 仅支持英译中。

事件说明沿用现有文案；运行时终端说明不在本次范围内。

## 相关概念

### 诊断说明

诊断说明描述代码中的问题，内容可能随用户编写的代码而变化，例如错误消息中的变量名和类型名。

### 文档说明

文档说明是语言服务在悬浮提示中提供的定义说明，包括类型和方法等。它通常由定义概览和说明文字组成，例如 `type int` 加上一段类型说明，或方法签名加上一段方法说明。

### 翻译

英文是语言服务内容的原始语言。用户选择英文时直接阅读原文；选择其他语言时，可以对诊断或文档说明发起 AI 翻译。翻译应保留原意及文中的代码标识符，不改写定义概览、链接等非说明内容。

### 译文与原文

用户语言为英文时只展示原文。用户语言为非英文时，点击“翻译”前只展示原文；翻译成功后同时展示译文和原文；翻译尚未完成或失败时仍只展示原文。

## 核心机制

### 翻译流程

诊断说明来自语言服务的诊断结果，文档说明来自语言服务的悬浮提示结果；两者在前端组成用户看到的悬浮提示内容。

用户点击“翻译”后，前端从相应结果中提取说明文字，结合该内容对应的代码上下文查找缓存；未命中时请求后端翻译。后端检查认证和限额，调用 AI 并返回译文。

### 翻译上下文

诊断翻译仅在用户点击“翻译”时读取当前诊断对应的代码行，必要时再取上下各两行，最多五行、1,000 个 Unicode 字符；超出时优先保留报错行。代码只用于帮助 AI 区分普通单词与变量、类型等代码名称。文档翻译可附带当前定义的概览，例如类型名或方法签名，最多 500 个 Unicode 字符，以帮助 AI 确定说明对象。

前端通过 `domain` 指明内容所属领域，后端选择对应的技能参考材料辅助翻译。未提供 `domain` 时使用通用翻译规则，使同一接口也能处理其他内容。

### 缓存与重复请求

前端在当前登录会话内缓存成功的译文，并合并同时发起的相同请求；缓存键包含 `content`、`targetLanguage`、`contentType`、`domain` 和 `context` 的完整值。只有键完全相同时才复用译文；代码或定义概览变化后重新请求。缓存最长保留 30 分钟，退出登录时清除，失败结果不缓存。用户再次点击已有译文时直接展示缓存结果。

现有 HTTP 请求封装不会自动缓存相同的 `POST` 请求；前端需为翻译调用显式使用应用内缓存。首版无需另建服务端缓存，后续可根据命中率和 AI 成本评估。

### 访问与用量

`POST /translations` 只向已登录用户开放，按用户单独计数，与 Copilot 配额分开。初始建议每用户每 24 小时最多 300 次实际 AI 翻译、每分钟最多 10 次请求。估算依据是一次较长编辑会话每分钟通常只会主动翻译少数不同内容；即使按每小时 20 次、一天 10 小时计算，也低于每日上限。上线后根据真实使用量和成本调整。

缓存命中与合并到同一次进行中请求的点击不重复消耗每日 AI 配额；到达每日配额时返回 `403`，超过每分钟频率时返回 `429`。后端须在调用 AI 前执行计数和限制，防止绕过前端缓存直接请求。

### API 边界

本功能新增 `POST /translations`，请求包含：

* `content`：从悬浮提示内容中提取的英文说明文字，不包含定义概览；不能为空，最多 12,000 个 Unicode 字符。
* `targetLanguage`：目标语言；当前仅支持简体中文 `zh-CN`。
* `contentType`：`diagnostic` 或 `documentation`，用于选择相应的翻译约束。
* `domain`：可选的领域标识；本次使用 `xgo` 或 `spx`。后端据此选择受控的技能参考材料，省略时使用通用翻译规则。
* `context`：可选的字符串。`contentType` 为 `diagnostic` 时是错误附近代码，为 `documentation` 时是定义概览；只用于消歧，不作为待翻译内容。使用同一个字段可避免 `codeExcerpt` 与 `definition` 两种子字段的组合和校验歧义。客户端分别遵守上述 1,000 和 500 字符上限，后端拒绝超过相应上限的请求。

`content` 和 `context` 都是用户提供的数据，构造 AI 提示词时不可将其中的文字当作指令执行。返回的 `translation` 作为纯文本转义后展示，不解析其中的 HTML 或链接；原文中已有的代码标识符与链接由原悬浮提示保持原样。整个 JSON 请求体最多 128 KiB。

例如翻译方法文档时，请求和响应分别为：

```json
{
  "content": "SetDefaultKnowledgeBase sets the default knowledge base for AI players.",
  "targetLanguage": "zh-CN",
  "contentType": "documentation",
  "domain": "spx",
  "context": "func SetDefaultKnowledgeBase(kb map[string]any)"
}
```

```json
{
  "translation": "SetDefaultKnowledgeBase 设置 AI 玩家的默认知识库。"
}
```

翻译诊断说明时，请求和响应分别为：

```json
{
  "content": "opponent is not a type",
  "targetLanguage": "zh-CN",
  "contentType": "diagnostic",
  "domain": "spx",
  "context": "opponent ai.Player"
}
```

```json
{
  "translation": "opponent 不是一个类型。"
}
```

### 错误处理

请求字段无效、超出字段长度或目标语言不受支持时返回 `400`，请求体超过 128 KiB 时返回 `413`，未登录时返回 `401`。每日配额耗尽返回 `403`，每分钟频率超限返回 `429`；AI 服务不可用或译文不可用时返回 `503`，超时返回 `504`。限额响应应告知可再次请求的时间。

前端在任一翻译错误下仍显示原文。诊断和文档独立翻译，一处失败不影响另一处。

## User Story

### 理解诊断说明

用户语言为非英文时，编辑项目写出一段有类型错误的代码。悬浮查看诊断时，先仅看到英文原文，点击“翻译”，完成后用户可对照阅读译文与英文原文；用户修改代码后，新的诊断说明需要重新翻译。

### 阅读文档说明

用户语言为非英文时，将鼠标悬浮在某个类型或方法上，先仅看到语言服务提供的英文文档。点击“翻译”，完成后用户可以对照阅读译文与英文原文，定义概览保持原样。
