## 设计考量

1. 减少初始选择：调用处只显示「查看定义」，声明处只显示「查看引用」。两者进入同一 Peek，避免查看与跳转两个平级入口。
2. 编辑规则一致：复用 `TextDocument.monacoTextModel → CodeOwner → History`，沿用项目保存行为。关闭、选择引用、展开和返回均不丢弃编辑，不另设保存确认。
3. 明确空间变化：展开图标的 Tooltip 为「在编辑器中打开」，不是浏览器全屏；打开当前预览位置，既可为定义，也可为引用。
4. 多位置可发现：通过「N 处引用」选择列表，按文档分组并显示行号和代码摘要；列表可滚动，用方向键选择、Enter 激活，Escape 先关闭列表。
5. 递归不特殊跳转：自递归调用及相互递归中的引用都来自同一语义查询，纳入列表。引用列表不是运行时调用栈，也不无限展开调用图。
6. 可返回：Peek 内的引用可「返回定义」；展开后沿用返回条，恢复打开 Peek 前的代码文档、光标、选区和滚动状态。多次展开逐级返回。
7. 不引入常驻侧栏：列表是临时选择器；窄编辑区内标题与操作允许换行，保留左右内边距及行号与代码的间距。
8. 信息随语言变化：标题、引用计数、加载/空/失败状态、返回、展开 Tooltip 同时支持中英文；角色名保持用户命名，Stage 采用已有文档显示名的本地化规则。

## 实现边界

- `ILSPClient` / `SpxLSPClient` 接入标准 `textDocument/references`，使用现有 WASM 语言服务，无新增后端或文本搜索替代。
- 引用查询使用 `includeDeclaration: false`，按 URI 和范围去重排序，仅展示当前项目可打开的代码文档。
- 定义与选中引用使用 Monaco 跟踪范围，插删代码后位置随模型更新；项目变化后防抖刷新引用，过期或关闭后的响应不会覆盖新状态。
- 失败不会伪装为零引用，允许重试。项目本身的语法/类型错误可能导致语言服务无法解析相关符号，此行为仍由语言服务决定。
- 普通代码输入不自动改写其他调用处；需要统一重命名时使用原有 Rename。
- Peek 中悬浮可重命名的符号也提供「重命名」，复用主编辑器的语义查询、弹窗、项目错误提示和单步撤销，不需返回调用处。悬浮定位和高亮属于 Peek 当前文档，不改变主编辑器的导航位置。

## 验收路径

### 1. 普通查看、编辑与返回

1. 在包含跨文档调用的项目中，例如 Match3 的 Board，悬浮 `getRowCol`。
2. 导航操作仅为「查看定义」，打开 Peek 后主编辑器仍保留 Board。
3. 定义标题显示文档及行号，Peek 右上角提供引用数量、展开、关闭。
4. 在 Peek 的函数中插入一条临时注释；关闭 Peek 后，在对应主编辑器中能看到同一修改；撤销可还原。
5. 重新打开 Peek，移动光标与滚动后展开；主编辑器保留该状态，显示「当前位置：舞台」及「返回 Board · 第 4 行」。
6. 点击返回，恢复打开 Peek 前的 Board 视图；不重新打开 Peek，不撤销代码修改。

### 2. 多处引用与递归

在无解析错误的测试项目中使用下列示例，避免改写正式项目内容。

舞台代码 `main.spx`：

```go
func factorial(n int) int {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)
}
```

角色代码 `Board.spx`：

```go
onStart => {
    println(factorial(5))
    println(factorial(3))
}
```

1. 从任一调用处查看定义，引用数量应为 3：Board 两处，舞台函数自身一处。
2. 从声明处悬浮，唯一导航操作为「查看引用」，打开 Peek 后立即显示引用列表。
3. 逐一选择三处引用，检查文档、行号、摘要与高亮。选择递归调用后不循环打开新面板。
4. 点击「返回定义」回到同一函数。展开某处引用后，返回入口仍回到最初发起查看的位置。
5. 验证两函数相互调用的情况；每个函数均可查询直接引用，不递归展开调用图。
6. 为定义上方插入一行，检查标题行号和查询位置跟随移动；增删调用后引用数量刷新。

### 3. 空态、操作与语言

- 无调用的函数：显示「0 处引用」，列表内明确说明当前项目中没有引用。
- 引用请求失败：显示失败和重试，不显示虚假的 0。
- 查询中切换符号或关闭 Peek：旧结果不闪回、不重新打开面板。
- 列表支持键盘上下选择，Escape 关闭列表；Peek 编辑区的 Escape 关闭 Peek 并回到主编辑区。
- 切换中文/英文，检查标题、行号、数量、空态、失败、返回和展开 Tooltip。
- 检查窄编辑区域：标题/按钮不互相覆盖，行号与代码不贴合，列表不挤压代码宽度，缩放控件保留。

### 4. 从 Peek 定义处重命名

1. 从 Board 调用处打开 Peek，悬浮定义中的函数名，点击「重命名」。弹窗默认名称应来自 Peek 中的符号，而不是 Board 光标所在处。
2. 输入新名称并取消：声明、调用处及 Peek 状态保持不变。
3. 再次打开并确认新名称：定义、跨文档调用、自递归调用一起更新，引用列表刷新；项目原本存在错误时沿用可能漏改引用的警告。
4. 使用项目撤销：同一次重命名涉及的声明和引用一起还原。关闭、展开或返回不丢失已确认的改动。
5. 切换 Peek 中的引用、滚动、编辑或关闭面板后，旧悬浮卡片及高亮不残留；中英文均可操作。

### 5. 修改参数并检查受影响调用

1. 打开函数定义 Peek，待引用数量加载完成，修改参数列表（新增、删除、顺序或类型）。编辑器出现「参数已修改」提示，保留修改前已识别的引用，包括递归引用。
2. 点击「检查调用」，在 Peek 中定位待检查位置。系统不会为新增参数猜测数值，也不会自动交换或转换实参。
3. 按实际意图修正调用，点击「已检查，查看下一处」。再次修改同一调用会清除该处检查标记，再改参数会清除全部标记。
4. 修改过程中临时删掉参数列表右括号，引用清单不应清空，且不能完成检查；补齐后继续。语言服务返回的新引用会补入清单，不替换掉旧位置。
5. 关闭或展开 Peek 后，检查提示保留，可通过「检查调用」继续；已有代码修改仍遵循原保存规则。
6. 检查期间点击「撤销本次调整」，参数及调用修正一起恢复，其他文件或非代码资产不回退。恢复操作本身进入项目历史，可用项目撤销恢复刚才的修改。
7. 在涉及文件中另改其他代码（如另一函数或调用行以外的内容），整组撤销应禁用并解释原因，不得覆盖这些改动；此时使用项目原有的逐步撤销。
8. 全部位置标记已检查后可「完成检查」。此按钮只结束检查流程，不是保存确认，也不代表编译通过；完成之后仍使用项目原有编辑历史撤销。

本地验收还使用了 Match3 舞台中的 `isSame`：查询到 22 处真实引用，在 Peek 为其新增演示参数 `strict bool` 后，显示「22 处调用待检查」，并可打开全部受影响位置。这是浏览器内的验收数据，不作为项目示例代码提交；在其他环境验收时，需要使用该环境中可访问的项目或上面的独立测试示例。

#### 参数检查的实现边界

- 当前语言服务不提供修改函数签名的自动重构接口。本轮提供检查与人工修正流程，参数名的语义重命名继续使用原有 Rename。
- 参数变化检测锚定语言服务给出的声明位置，读取配对的参数括号，兼容多行、嵌套函数类型、注释和字符串；不以文本搜索代替语义引用查询。空白及注释变化不触发检查。
- 仅检测参数列表，不承诺接收者、类型参数或返回值变化的自动检查，也不实现参数值推断、类型转换和实参自动重排。
- 「已检查」是用户的人工确认；应结合现有错误提示和运行结果验证正确性。项目原有错误仍可能使语言服务无法提供完整引用。
- 整组撤销仅在检查期间、且修改能限定在已记录参数及引用行范围内时提供。函数体其他位置的修正或其他混合编辑也会保守地禁用此入口，避免把不属于本次调整的代码一起覆盖；它不替代项目历史。
- 首次修改前引用尚未加载完整时，明确提示撤销本次调整并等待引用，不能把未知引用数量当成零。检查进度是当前编辑会话状态，不跨页面刷新持久化。
